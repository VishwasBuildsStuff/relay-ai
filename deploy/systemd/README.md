# Single-host systemd templates

These units provide a localhost-only FastAPI/worker service and a daily backup for a dedicated Linux host. They are templates: replace the example paths and configure the host before enabling them.

1. Install the repository and Python environment under `/opt/relay-ai`; install Node-built static assets behind a TLS reverse proxy or serve them separately.
2. Build the sandbox image using the pinned base in `relay-ai/sandbox/Dockerfile`; capture its full image ID and set `RELAY_SANDBOX_IMAGE=sha256:...` in `/etc/relay-ai/relay-ai.env`. Create that file with protected permissions (`root:relay-ai`, mode `0640`). Set at least `GEMINI_API_KEY`, `RELAY_DB_PATH=/var/lib/relay-ai/relay_tasks.sqlite3`, `RELAY_APPLIED_ROOT=/var/lib/relay-ai/applied`, explicit `RELAY_CORS_ORIGINS`, and unique `RELAY_AUTH_USERS_JSON`/`RELAY_AUTH_ROLES_JSON` values. Do not set `RELAY_ENV` in this file; the unit sets production mode, which fails startup if auth, explicit CORS, or a digest-pinned sandbox image is missing, or unsafe subprocess mode is enabled. Add `RELAY_REPOSITORIES_JSON` only for trusted local Git roots.
3. Create `/var/lib/relay-ai` and `/secure/backups/relay-ai` owned by the service account. Add each configured repository root to the service unit's `ReadWritePaths` and grant access only to those roots.
4. Install the units to `/etc/systemd/system`, then run `systemctl daemon-reload`, `systemctl enable --now relay-ai.service`, `systemctl enable --now relay-ai-backup.timer`, and `systemctl enable --now relay-ai-backup-age-check.timer`.
5. Install `deploy/nginx/relay-ai-proxy-location.conf` as `/etc/nginx/snippets/relay-ai-proxy-location.conf` and `deploy/nginx/relay-ai.conf` under `/etc/nginx/conf.d/`. Replace `relay.example.com` and certificate paths, run `nginx -t`, then reload Nginx. Set `RELAY_CORS_ORIGINS` to bare HTTPS origins (for example, `https://relay.example.com`); production startup rejects paths, credentials, wildcards, and non-HTTPS origins. The sample applies 1 MiB general, 10 MiB JSON submission, and 27 MiB multipart upload caps; 20 concurrent connections per source IP; 20 requests/second with a burst of 40; and explicit request/upstream timeouts. The systemd unit binds to `127.0.0.1:8000`, trusts forwarded headers only from that address, and must not be exposed directly to an untrusted network.

The Nginx config overwrites `X-Forwarded-For` with its observed peer address and sends the scheme/host itself. Do not trust caller-supplied forwarding headers. If Nginx is behind a load balancer, configure real-IP handling only for that load balancer's trusted source CIDRs before using the client IP for rate limits.

The sandbox expects Docker. Giving the service account membership in the host `docker` group is root-equivalent; use a narrowly restricted Docker socket proxy or accept that host-level risk deliberately. The unit does not grant Docker access by itself. Configure and test the chosen socket path separately.

Each backup is verified before the tool atomically publishes its final filename. The age-check timer exits nonzero when no archive exists or the newest archive exceeds 26 hours; connect failed systemd units to an external alerting system. Operators must assign an owner and periodically restore into an isolated environment. Do not treat these example units as a production security certification.
